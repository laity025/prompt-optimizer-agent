# 系统架构与技术选型语料库

**主题：** 提示词自动迭代优化智能体系统架构与技术选型
**适用范围：** 系统架构师、后端开发、前端开发、运维人员
**版本：** v1.0

---

## Q: 本项目的整体系统架构是什么？

**A:** 采用前后端分离的 B/S 架构，整体分为前端展示层、后端服务层、数据存储层与 AI 能力层：
1. 前端展示层：负责任务创建、迭代可视化（得分曲线/版本对比/评分理由）、最优提示词导出
2. 后端服务层：用户认证、变体生成与批量执行、自动指标计算、评审打分、迭代循环编排、数据存储
3. 数据存储层：sqlite3 存储用户、任务、提示词版本、测试用例与评测记录
4. AI 能力层：LLM API 提供变体生成、任务执行与评审打分

**标签：** 系统架构, 前后端分离, B/S架构, 分层设计

---

## Q: 本项目的技术选型有哪些？

**A:** 核心技术选型如下：
- 开发语言：Python 3.12+
- 大语言模型：LLM API（国内直连，OpenAI 兼容接口）
- Agent 框架：LangGraph（生成—执行—评估—择优的迭代循环编排）
- 评估工具：NLTK / rouge（BLEU、ROUGE 等自动指标）
- 数据处理：pandas / NumPy（迭代记录统计与得分分析）
- 后端服务：FastAPI（RESTful API 与异步任务）
- 前端框架：React（Web 界面）
- UI 组件库：TailwindCSS / Ant Design（视觉按皇家蓝作品集风格落地）
- 数据库：sqlite3

**标签：** 技术选型, Python, FastAPI, React, LangGraph, sqlite3

---

## Q: 为什么选择 LangGraph 作为迭代编排框架？

**A:** LangGraph 支持将有循环的状态图模式引入 LLM 应用，非常适合本项目的「变体生成→任务执行→质量评估→择优更新→终止判断」带循环的迭代编排，能清晰表达状态流转、维护每轮循环的状态对象，并支持人工介入（停止/冻结/回退）与断点延续。

**标签：** LangGraph, 循环编排, 状态图, 迭代控制

---

## Q: 为什么选择 NLTK / rouge 作为自动指标工具？

**A:** NLTK 与 rouge 是开源的评测指标库，可直接计算 BLEU（n-gram 重叠）与 ROUGE（如 ROUGE-L）等经典文本质量指标，代码已有、经社区验证、计算准确，适合作为提示词输出质量的自动评估工具。

**标签：** NLTK, rouge, BLEU, ROUGE, 自动指标

---

## Q: 后端为什么选用 FastAPI？

**A:** FastAPI 基于 Python 3.12+，具有高性能异步支持、自动生成 OpenAPI 文档、Pydantic 数据校验、依赖注入等特性，非常适合本项目的 RESTful API 与异步批量任务编排。

**标签：** FastAPI, 异步, 自动文档, Pydantic, 依赖注入

---

## Q: 前端为什么选用 React + Vite？

**A:** React 组件化开发便于实现任务列表、创建表单、迭代看板等页面；Vite 提供快速的开发服务器与打包；结合 TailwindCSS / Ant Design 组件库可高效构建响应式界面与得分曲线、版本对比等可视化组件。界面整体遵循「皇家蓝作品集风格」：皇家蓝 #0E4AC3 实心块选中态、超大黑色中英对照标题、浅灰底 #E9E9EB、点前缀序号 ·01 与 1px 细线。

**标签：** React, Vite, TailwindCSS, Ant Design, 组件化, 皇家蓝

---

## Q: 系统支持哪些目标任务类型？

**A:** 支持文案生成、文本摘要、信息抽取、代码生成四种内置任务类型，每种类型对应不同的任务模板、评分标准建议与自动指标建议，也支持自定义任务类型。

**标签：** 任务类型, 文案生成, 文本摘要, 信息抽取, 代码生成

---

## Q: 系统如何保证用户数据隔离？

**A:** 采用按用户隔离的多租户设计：用户注册登录后，系统为每个用户维护独立的数据库记录集合，优化任务、提示词版本与评测数据均标记所属用户，前后端在接口层校验资源属主，用户只能访问自己的数据。

**标签：** 数据隔离, 多租户, 权限校验, 用户认证

---

## Q: 后端如何组织业务服务？

**A:** 后端采用分层组织：api/endpoints 承载接口入口，services 承载业务逻辑（如变体生成、批量执行、自动指标、评审打分、迭代编排、报告生成），models 定义数据库模型，schemas 定义 Pydantic 校验，core 存放配置与安全工具，llm 封装大模型客户端。

**标签：** 后端分层, api服务, 业务服务, 模型, Pydantic

---

## Q: 系统如何支持异步批量执行？

**A:** 迭代执行采用异步任务机制：开始迭代接口立即返回，后台异步任务基于 LangGraph 编排循环，通过进度接口供前端轮询获取实时进度，支持并发执行与失败重试，任务被停止后支持断点续跑。

**标签：** 异步任务, 并发执行, 进度轮询, 断点续跑

---

## Q: 系统的部署方式是什么？

**A:** 采用前后端分离部署，前端构建为静态资源，后端为 FastAPI 服务，通过 Nginx 反向代理对外提供服务，支持 HTTPS 加密传输，适配主流浏览器。

**标签：** 部署, Nginx, HTTPS, 反向代理, 静态资源

---

## Q: 系统如何对接大语言模型 API？

**A:** 通过统一的 LLM 客户端封装调用 OpenAI 兼容接口，支持指定模型、温度与最大 token，支持结构化输出（JSON 模式）、超时与重试、敏感字段脱敏，实现国内直连并可切换不同服务商。

**标签：** LLM API, OpenAI兼容, 模型调用, 结构化输出, 脱敏
