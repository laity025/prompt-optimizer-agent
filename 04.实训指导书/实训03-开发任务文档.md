## 一、实训目标

1. 掌握将 PRD 需求转化为可执行开发任务的**工作分解方法**（WBS：需求 → 模块 → 任务 → 子任务）。
2. 学会为每个开发任务编写**任务描述、输入输出、依赖关系、进度排期**与**验收标准**。
3. 理解 P0 → P7 阶段排期与「任务书 10 项 → 模板交付物」的映射关系。
4. 掌握使用 AI 共创方式辅助拆解任务、补充验收标准与发现遗漏的提示词写法。
5. 能够独立产出一份结构完整、可落到开发周期的「开发任务文档」。

## 二、实训内容

### 1. 背景知识

从 PRD 到代码之间，需要一份「**开发任务书**」作为承上启下的桥梁。PRD 回答「做什么」，开发任务书回答「分几步做、每步做什么、做完怎么验收」。「AI 共创教学实训项目」通常遵循如下拆解链路：

```
需求（PRD） → 模块拆解（WBS） → 开发任务 → 依赖关系 → 阶段排期（P0-P7）
                                          ↓
                           每个任务：描述 + 输入/输出 + 依赖 + 验收标准
```

关键概念：

- **WBS（工作分解结构）**：把产品大目标逐层拆细到可执行的最小任务单元，避免「一口吃成胖子」。
- **阶段（Phase，P0-P7）**：项目的高层时间切分，见《项目整体规划》第八节。
- **验收标准（Definition of Done）**：任务完成的客观条件，只有能被验证的命令/行为才算完成。
- **AI 共创拆解**：让大模型扮演「资深全栈开发 / 项目管理」角色，帮我们把大模块拆成带依赖与验收的子任务，再人工审校。

## 五、故障排除

### 问题1：拆解任务过多或过细

**现象：** 子任务粒度太碎，排期表爆长，难以管理。

**解决方案：** 以「1-3 人天内可完成」为粒度，把过于细碎的子任务合并为一个任务单元；匹配项目规模调整 WBS 层级。

### 问题2：AI 拆解结果与 PRD 不一致

**现象：** 大模型补充了 PRD 中没有的功能，或漏掉了 PRD 强制规则。

**解决方案：** 在提示词中显式写入「仅基于给定文档，不得新增需求」；对 AI 输出逐条对照 PRD 校验，删除越权项、补回遗漏项。

### 问题3：排期存在循环依赖

**现象：** 任务 A 依赖 B 的同时 B 又依赖 A。

**解决方案：** 重新梳理数据流向：数据库建模先行、服务层承载业务、API 暴露能力、前端消费。无法打破时引入中间任务切面（如先建桩接口再并行）。

### 问题4：验收标准不可验证

**现象：** 验收标准写成「优化效果更好」这类主观描述。

**解决方案：** 改成可执行命令或可量化行为，例如「`Test-Path` 返回 True」「接口返回 `code=0`」「单轮 4×5 样例耗时 ≤ 60 秒」。

### 问题5：交付物与阶段混淆

**现象：** 文档类产出（PRD、测试报告）误排进代码开发阶段。

**解决方案：** 依《项目整体规划》第八节，文档产出归 P1/P6/P7，代码产出归 P3/P4/P5，按输出类别分区排期。

### AI 共创拆解任务提示词示例

```
角色：你是一位资深全栈开发工程师兼软件项目经理，精通 FastAPI、LangGraph、React 与 SQLite。
任务：请把下面的产品模块拆解为可执行的开发任务书。

约束：
- 仅基于下方给定的文档内容，不得新增 PRD 之外的需求。
```
