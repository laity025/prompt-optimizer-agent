## 二、实训内容

### 1. 背景知识

#### 1.1 UI 与 UX 的界定

- **UX（User Experience，用户体验）**：关注产品的信息架构、交互流程、状态反馈，回答「用户要完成一件事，每一步看到什么、能做什么、如何获得反馈」。
- **UI（User Interface，用户界面）**：关注页面具体的视觉呈现，回答「每个元素长什么样、色彩字体、对齐留白」。
- 本项目 UI/UX 设计文档把两者合为一篇，先定设计原则与信息架构（UX 侧），再落地到核心页面与视觉规范（UI 侧），最后用「关键流程」串起交互。

#### 1.2 本产品的设计主线

页面围绕一个核心价值闭环组织：**创建任务 → 观察迭代 → 获取最优提示词**。所有设计都服务于「清清楚楚地看到提示词在被自动变好」这一个人可感知的结果。由此衍生设计原则：

| 原则 | 落地要点 |
|------|---------|
| 清晰优于炫技 | 视觉统一克制，不堆装饰，突出信息 |
| 过程可视化 | 得分曲线、版本差异、评分理由是核心价值，必须有直观呈现 |
| 关键操作低摩擦 | 新建任务 / 开始迭代 / 导出报告三个高频操作入口明确可达 |
| 状态可见 | 待运行 / 运行中 / 已完成 / 已停止每一步都有明确状态标识 |
| 响应式 | 桌面 ≥1280px 与移动 ≥375px 均可用，主操作不遮挡 |

#### 1.3 与前端技术栈的对应

UI/UX 设计要可直接指导 P4 前端开发，因此设计产物需与前端技术栈对齐：

- **布局与路由**：信息架构的导航与页面树对应 React Router 路由；左侧导航对应 AntD Layout 组件，页面树分层为「任务 / 创建任务 / 迭代看板 / 报告归档 /（管理）系统日志 /（管理）用户管理」。
- **组件库**：表单、按钮、表格、弹出确认、消息反馈对应 Ant Design 5 组件；间距 / 色彩 / 栅格通过 Tailwind 的 utility class 落地。
- **视觉基线**：全站统一为「皇家蓝作品集风格」（V2.0）——浅灰底 `#E9E9EB` + 皇家蓝 `#0E4AC3` 实心块 + 超大黑色中英对照标题（如 `Tasks ／ 任务`）+ 3D 流体渐变图形 + 黑色小人 IP + 点前缀序号 `·01` + 1px 细线；任何组件不得跳出该视觉体系。
- **图表**：得分曲线对应前端图表库（Chart 类组件折线图），折线色为皇家蓝 `#0E4AC3`，面积为皇家蓝→透明渐变。

#### 1.4 页面清单总览

典型的信息架构（范例 UI/UX 第三节）：
```

├── 登录 / 注册
├── 主界面（登录后）
```

#### 1.5 设计产物应包含的「状态」三要素

每个页面都要写清：**空态**（没有数据时）、**错误态**（校验/请求失败时）、**成功态**（操作成功后）。这是 UI/UX 文档常被初学者忽略、却最能决定实际体验的一环。

### 步骤3：AI 共创 —— 用大模型辅助生成页面布局与交互草稿

**详细说明（AI 共创提词技巧，本实训重点）：**

做 UI/UX 的 AI 共创要传递「页面清单 + 每页职责 + 交互细节 + 视觉约束 + 状态要求」，并让模型按统一模板输出。以下 3-5 条提问 / 协作提示词可作为本实训直接使用的示例（务必按自己任务改写）：

**提示词 A（生成信息架构与页面清单）：**

> 请输出：1) 用树形结构列出全部页面与子页签；2) 每个页面的定位与核心职责一句话；3) 页面之间的跳转关系。前端技术栈为 React18+Vite+AntD5+Tailwind。请用 Markdown 代码块输出树形结构。

**提示词 B（展开单个核心页面的布局+交互+状态）：**
> 请针对「任务详情页 — 迭代过程子页」输出详细设计：1) 布局骨架用从导航、卡片、图表区、列表区的文字分区描述；2) 交互包括运行中进度轮询（1.5 秒）、失败用例标红并悬浮显示原因、得分曲线逐轮增长；3) 状态分别描述待运行 / 运行中 / 已完成 / 已停止 / 失败重试五种情形下的界面呈现；4) 异常（单用例调用失败）如何不影响其他用例继续。请按【布局 / 交互 / 状态 / 异常】四小节输出。

## 五、故障排除

### 问题1：`Select-String "视觉规范"` 匹配过多 / 缺失

**现象：** 同时命中多个标题，或想精确匹配「五、交互与视觉规范」却遗漏。

**解决方案：** 使用更精确的锚定；标题含编号「五、」时匹配编号前缀：
```powershell
Get-Content "...\UIUX设计文档.md" -Raw | Select-String "五、交互与视觉规范"
```

### 问题2：在线编辑器 / PowerShell 打开中文 UTF-8 显示乱码

**现象：** 草稿文件用 PowerShell 或旧版记事本打开中文乱码。

**解决方案：** 统一以「UTF-8 或带 BOM」保存；Write / Edit 生成后，用 `Get-Content -Encoding UTF8` 读取验证再定稿；避免在 GBK 编码系统脚本中追加中文。

### 问题3：LLM 生成的页面设计缺「状态」描述

**现象：** 只给了正常态布局，没有空态 / 错误态。

**解决方案：** 用提示词 B 明确要求「分空态 / 错误态 / 成功态描述」，并主动向模型列举可能的异常（如空用例集、用例调用失败、评审失败兜底），让它逐态作答。

### 问题4：设计稿色彩 / 数值离散，无法当 design token 用

**现象：** 出现 @色值 分散、或圆角 / 间距数值（如 8px / 12px / 16px）不统一。

**解决方案：** 用提示词 C 让模型输出变量命名表（如 `--color-primary`）并归拢间距步进（建议 4px 或 8px 基准），再人工校核为紧凑 token 集合。

### 问题5：信息架构页面树与 PRD 模块对不上

**现象：** 某些 PRD 功能在页面树里找不到落脚点。

**解决方案：** 对照步骤1 的「PRD 模块→页面」映射表逐项核对；若缺页，用提示词 A 让模型基于十大模块重新生成页面树，再人工确认覆盖度 10/10。
