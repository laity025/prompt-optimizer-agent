## 二、实训内容

### 1. 背景知识

#### 1.1 什么是「提示词自动迭代优化智能体」

提示词（Prompt）是决定大语言模型应用效果的关键变量：同一任务，提示词的措辞、结构与约束不同，模型输出质量可能天差地别。传统做法依赖人工手动试错，代价高昂且缺乏评估手段。

本项目将提示词优化建模为一个「**生成变体 → 执行任务 → 质量评估 → 择优迭代**」的闭环：由智能体根据优化目标自动生成提示词变体，调用大语言模型执行真实任务，用自动指标（BLEU / ROUGE / 关键词命中 / 格式合规）与评审打分（大模型按评分标准给出 1-10 分）评估输出质量，循环择优迭代直至收敛，最终输出最优提示词、得分曲线与优化报告。

用户通过浏览器即可创建优化任务、设定优化目标与测试用例集，观察得分变化曲线并导出最优提示词。产品最终形态是一个前后端分离的 Web 应用（WebApp）。

#### 1.2 为什么先写 PRD

PRD（Product Requirement Specification，产品需求规格说明书）是 AI 共创开发流程中「P1 需求设计」的核心交付物，是后续 UI/UX 设计、数据库设计、API 设计乃至前后端开发的事实依据。一份合格的 PRD 需要解决三个问题：

- **做什么**：产品的总体目标与量化指标。
- **怎么做**：每个功能模块的页面布局、业务逻辑、关键规则。
- **做到什么程度**：非功能性要求（合规、隐私、可靠性、性能）与边界情况。

#### 1.3 核心概念（自 PRD 术语表提炼）

| 术语 | 说明 |
|------|------|
| 提示词变体 | 基于当前提示词改写生成的多个候选版本 |
| 最优提示词 | 迭代过程中综合得分最高的提示词版本 |
| 测试用例集 | 一组输入（可含参考输出），用于执行与评估提示词效果 |
| 参考输出 | 人工为测试用例标注的理想输出，用于计算自动指标 |
| bad case | 得分差 / 不满足要求的用例，用于指导下一轮变体生成 |
| 评审打分 | 大模型按评分标准对输出质量的 1-10 分量化评分 |
| 收敛 | 最优得分连续若干轮不再提升的终止条件 |
| 自动指标 | BLEU、ROUGE、关键词命中、格式合规等可计算评估指标 |

#### 1.4 本项目的关键业务闭环

```
设置优化目标、任务描述、测试用例集、初始提示词
    ↓
[变体生成] 基于当前最优 + 失败案例生成 N 个候选（默认 4）
    ↓
[任务执行]  每个变体逐条执行全部测试用例，失败自动重试
    ↓
[质量评估]  自动指标（本地计算）+ 评审打分（LLM，1-10 分）→ 加权合成综合得分
    ↓
[择优迭代]  本轮最高分作为下一轮基准，判断是否终止（达标 / 收敛 / 达最大轮次）
    ↓
输出最优提示词、得分曲线、优化报告
```

#### 1.5 量化目标（必须写入 PRD）

| 指标 | 目标值 |
|------|--------|
| 综合得分较初始版本提升 | ≥30% |
| 自动评审与人工评分一致率 | ≥80% |
| 单轮迭代平均耗时（含变体生成与全量评测） | ≤60 秒（视用例规模） |
| 任务执行成功率 | ≥98% |

#### 1.6 本项目的扩展能力（新增模块）

在核心优化闭环之上，产品已扩展出 5 个周边能力模块，使提示词资产可复用、可交付、可评测：

| 扩展模块 | 核心价值 | 关键能力 |
|---------|---------|---------|
| 知识库管理（RAG） | 为任务注入领域上下文 | 建库/语料上传/一键导入示例语料；嵌入向量 + 词法指纹双模式检索；RAG 检索+生成评测（来源支撑度、忠实度 0-100） |
| 在线服务（API 调用） | 将提示词快照发布为可调用端点 | `X-Api-Key` 鉴权、密钥轮换（HMAC 恒定时间比较）、按端点限流（60 次/分钟）、调用日志与统计（SQL 聚合） |
| 模型评测平台 | 多模型横向对比同一提示词 | 多模型×用例得分矩阵、最优模型推荐、评测报告导出、跨任务评测历史 |
| 多步骤工作流 | 把单任务拆成多步骤链式执行 | 指令模板占位符（`{{input}}` / `{{stepN.out}}`）、基线对照评测、步骤级多轮优化（轮次 1/2/3/5） |
| 报告分享与仪表盘 | 资产沉淀与可视化 | 报告免登录分享链接（token 机制、可设有效期）、分享撤销；资产总览仪表盘（任务/知识库/端点统计、趋势、模型分布、版本库） |

#### 1.7 合规与隐私要求（非功能性需求的核心）

- **内容合规**：依据《互联网信息服务深度合成管理规定》，对 AI 生成的提示词变体、任务输出与评审意见以显著方式标识；优化结果仅供参考，正式使用前应经人工确认。
- **数据隐私**：支持 HTTPS 加密传输、数据库安全存储与本地化部署；调用大模型 API 前对敏感字段脱敏；不得将任务数据用于服务以外用途或向第三方提供。
- **模型局限**：保留人工抽检通道，用于校准自动评审，支撑「一致率≥80%」指标采集。

### 步骤3：AI 共创 —— 用大模型辅助撰写 PRD 结构草稿

**详细说明（AI 共创提词技巧，本实训重点）：**

「AI 共创」不是把写作外包给大模型，而是 **人机协作**：人类给出高质量上下文与约束，大模型产出结构草稿，人类负责校验、纠偏与定稿。撰写 PRD 时，向 LLM 提供以下四类信息效果最好：

1. **角色指令**：告诉 LLM 扮演「资深软件产品经理 + PRD 审校专家」。
2. **足够上下文**：粘贴项目背景、技术栈、量化指标、功能模块清单。
3. **明确输出格式**：要求按「背景→目标→功能详述→非功能→术语表」的结构输出，功能详述要含页面布局、业务逻辑、关键规则三子段。
4. **请它提问与自审**：让 LLM 先补充遗漏、再自我审查逻辑矛盾。

以下是本实训可直接用到的 3-5 条提问 / 协作提示词（示例，务必根据自己的任务改写后再发给模型）：

> 项目背景：通过「生成变体→执行任务→质量评估→择优迭代」闭环自动优化提示词，输出最优提示词、得分曲线与报告；并在闭环之上提供知识库 RAG 增强、在线 API 服务、多模型评测、多步骤工作流与报告分享/仪表盘等扩展能力。技术栈：Python 3.12 / FastAPI / LangGraph / React18+Vite+AntD5+Tailwind / llm API（OpenAI 兼容）。

**提示词 B（补齐一版更细的需求）：**

## 五、故障排除

### 问题1：PowerShell 读取中文文件乱码

**现象：** `Get-Content` 打印 PRD 中文出现乱码。

**解决方案：** 文件为 UTF-8 编码时显式指定编码读取；若仍乱码，可能是文件含 BOM 或 GBK，可显式迁移：
```powershell
Get-Content "d:\...\提示词自动迭代优化智能体_PRD文档.md" -Encoding UTF8 | Out-Null
# 若文件名含中文匹配失败，先用 Get-ChildItem 定位真实文件名再读取
Get-ChildItem "d:\trae_project\提示词自动迭代优化智能体\04.实训指导书\AI共创过程文档" | Select-Object Name
```

### 问题2：`Select-String "^## "` 匹配不到章节标题

**现象：** 明明有 `## 一、` 标题却匹配失败。

**解决方案：** Windows 文件常带 UTF-8 BOM 导致首行匹配异常；改用 `-Raw` 后正则匹配，或放宽为匹配 `一、`：
```powershell
Get-Content "d:\...\PRD文档.md" -Raw | Select-String "一、需求背景"
```

### 问题3：LLM 生成的 PRD 内容空泛、缺少字段级细节

**现象：** 模型输出大段描述但无具体字段、数值、规则。

**解决方案：** 用提示词 B 二次追问，明确要求「输出到字段级、给出取值范围与兜底规则」，并附实例句；避免使用「请详细一点」这类无具体约束的措辞。

### 问题4：用例集 JSON 解析失败

**现象：** `json.load` 抛 `UnicodeDecodeError` 或 `JSONDecodeError`。

**解决方案：**
```powershell
# 显式指定 UTF-8 编码读取
python -c "import json;print(json.load(open(r'd:\...\test_cases_extraction.json',encoding='utf-8'))['dataset_id'])"
```

### 问题5：不确定 PRD 与数据库 / API 设计文档的衔接是否一致

**现象：** 后续文档与 PRD 术语或功能不一致。

**解决方案：** 以 PRD 为唯一事实源；对「综合得分/收敛/状态流转」等关键定义在 PRD 中建立集中定义区，后续文档引用而非复述，并用提示词 C 做跨文档一致性自审。
