# 提示词自动迭代优化智能体 —— 数据库设计文档

| 项目 | 内容 |
|------|------|
| 文档版本 | V2.0.0 |
| 数据库 | SQLite（本地文件，后续可迁移至 PostgreSQL/MySQL），共 22 张表 |
| 配套 PRD | 《提示词自动迭代优化智能体_PRD文档.md》 |

---

## 一、设计说明

系统采用 SQLite 作为主存储，满足用户隔离、任务持久化、迭代版本快照、评测记录留痕、RAG 知识库、在线服务、多模型评测、多步工作流与报告分享的需求。数据库遵循四点原则：

1. **数据按用户隔离**：一切业务表（任务、用例、版本、评估结果、知识库、端点、评测、工作流、分享）均含 `user_id` 属主字段。
2. **版本全量留痕**：迭代的每一轮、每个变体、每条评估记录都持久化，支持回溯与回退；工作流步骤优化同样逐轮逐变体留痕。
3. **结果可复现**：任务执行结果（模型输入输出、指标得分、评审理由）完整保存，一事一记录；端点调用日志记录每次外部调用的输入输出与耗时。
4. **原子一致**：知识库文档/块计数、端点调用计数等并发写场景使用 SQL 原子自增（`update ... values(count=count+1)`），禁止 ORM 对象 `+=` 后 commit，避免并发丢更新。

数据库文件：本项目独立文件 `prompt_optimizer.db`（默认位于 `backend/app/` 目录，可通过 `DATABASE_URL` 配置路径）。

## 二、实体关系概览

```
users 1 ── n tasks                 # 用户创建多个任务
tasks 1 ── n test_cases            # 任务包含多个测试用例
tasks 1 ── n prompt_versions       # 任务产生多版提示词
tasks 1 ── n iterations            # 任务的每轮迭代
iterations 1 ── n variants         # 每轮迭代生成多个变体
variants 1 ── n eval_results       # 每个变体在多个用例上的评估结果
tasks 1 ── n operation_logs        # 用户操作留痕（管理员审计）
users 1 ── n knowledge_bases       # 用户的知识库（RAG）
knowledge_bases 1 ── n knowledge_docs        # 库内多份语料文档
knowledge_docs 1 ── n knowledge_chunks       # 文档切分为多个检索块
tasks n ── 0..1 knowledge_bases    # 任务可绑定知识库开启 RAG（kb_id, enable_rag）
users 1 ── n service_endpoints     # 用户发布的在线端点（绑定任务提示词快照）
service_endpoints 1 ── n endpoint_call_logs   # 端点调用日志
users 1 ── n benchmark_runs        # 多模型对比评测运行
benchmark_runs 1 ── n benchmark_results       # 单模型单用例评测明细
users 1 ── n workflows             # 多步工作流模板
workflows 1 ── n workflow_steps    # 工作流按 seq 串联的步骤
workflows 1 ── n workflow_runs     # 工作流执行运行
workflow_runs 1 ── n workflow_results         # 单用例端到端结果（含步骤追踪/基线对照）
workflows 1 ── n workflow_step_optimizations  # 步骤级优化运行
workflow_step_optimizations 1 ── n workflow_step_opt_variants  # 每轮变体与打分
users 1 ── n report_shares         # 报告分享链接（免登录只读访问）
```

## 四、字段设计与约束说明

1. **时间戳统一使用** ISO 8601 字符串（本地时区），便于存储与展示。
2. **密码**仅存 bcrypt 哈希，不存明文；端点 API 密钥以 `sk-` 前缀随机生成并整体存储，鉴权使用 HMAC 恒定时间比较。
3. **关键词**以 JSON 数组字符串存储（如 `["关键词1","关键词2"]`）。
4. **关联删除**：删除任务时，级联删除其用例、版本、迭代、变体、评估结果、绑定端点与工作流；删除用户同理；删除被任务绑定的知识库前必须先解除任务引用（`update tasks set kb_id=null, enable_rag=0`），避免悬空外键。
5. **并发安全**：迭代执行由后端异步任务驱动，轮次写入使用事务，避免重复创建同轮记录；知识库 doc_count/chunk_count、端点 call_count、分享 view_count 均用 SQL 原子自增。
6. **权限校验**：每次访问业务数据时，通过 `user_id` 强校验属主；工作流运行与步骤优化数据必须通过 `workflow_id` 关联过滤属主，防止跨租户泄露；分享链接仅校验 token，访问目标报告内容经 user_id 隔离。
7. **快照设计**：评测/工作流/分享等扩展模块中的用例引用（test_case_id）与任务关联（task_id）以快照方式存储（不强制外键），保证历史运行结果不受源数据删除影响。
8. **工作流约束**：创建时步骤列表不可为空模板/空列表（与前端校验一致）；同一工作流并发发起执行由后端工作流粒度锁（asyncio.Lock）串行化，防止重复运行。

## 五、迁移与备份

- 开发期使用 SQLAlchemy `create_all` 建表；生产环境引入 Alembic 迁移管理。
- 对历史 SQLite 库增量补充新列（如 tasks 表 `kb_id`/`enable_rag`）使用 `reconcile_apply.py` 脚本按列存在性增量添加，避免 `no such column`。
- 任务与评测数据支持导出为 JSON（供报告导出与备份）。
- 支持本地化部署，数据库文件随应用目录迁移。
