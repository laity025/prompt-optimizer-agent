## 一、需求背景

提示词是决定大模型应用效果的关键变量：同一任务，提示词的措辞、结构与约束不同，输出质量可能天差地别。AI 应用开发者、产品经理与内容创作者在构建 AI 应用时，普遍依靠手动试错调整提示词。少数派文章作者自述「花了 1000 次迭代把我的 APP 提示词从 30 分提到 90 分」，生动反映了手动优化的高昂代价；非专业用户更缺乏系统评估方法，难以判断一版提示词是否真的变好，导致 AI 应用效果不稳定、上线质量参差 `[Research-backed]`。

大模型与自动评估技术的成熟为这个问题提供了新解法：将提示词优化建模为「生成变体 → 执行任务 → 评估打分 → 择优迭代」的闭环，由智能体根据优化目标自动生成提示词变体，调用大模型执行真实任务，用自动指标与评审打分评估输出质量，循环迭代直至收敛，最终输出最优提示词与优化报告 `[PM judgment]`。

随着 Web 技术的发展，基于浏览器的 Web 应用具有跨平台、无需安装、易于传播等优势，用户通过浏览器即可创建优化任务、观察迭代得分曲线并导出最优提示词。

---

## 二、需求目标

### 2.1 总体目标

开发一款基于智能体编排的提示词自动迭代优化 Web 应用：用户通过浏览器设定优化目标、任务描述、测试用例集与初始提示词，系统自动生成提示词变体，调用大模型 API 执行目标任务（文案生成、文本摘要、信息抽取、代码生成等），按自动指标与评审打分评估输出质量，循环择优迭代并展示得分变化曲线，最终输出最优提示词、优化报告与历史版本对比。

### 2.2 量化目标

| 指标 | 目标值 |
|------|--------|
| 综合得分较初始版本提升 | ≥30% |
| 自动评审与人工评分一致率 | ≥80% |
| 单轮迭代平均耗时（含变体生成与全量评测） | ≤60 秒（视用例规模） |
| 任务执行成功率 | ≥98% |

## 三、功能需求详述

本产品包含 10 大功能模块。核心模块（3.1-3.5）构成「变体生成 → 执行 → 评估 → 择优迭代」优化闭环；扩展模块（3.6-3.10）将提示词资产沉淀为可复用、可交付、可评测的能力。以下按模块逐一说明页面布局、业务逻辑与关键规则。

### 3.1 优化任务管理模块

#### 页面布局

本模块由三个区域构成：

- **任务列表区**：展示用户已创建的优化任务，支持新建与筛选。
- **任务创建表单区**：用于录入任务描述、优化目标、评分标准，添加或导入测试用例集。
- **任务类型模板选择区**：提供文本生成、文本摘要、信息抽取、代码生成等预置模板，选择后自动填充任务描述与评分标准骨架。

#### 业务逻辑

用户在任务列表页点击「新建任务」，进入创建表单。系统先让其选择目标任务类型：若选择预置模板（如信息抽取），自动写入任务描述模板、推荐评分标准与适用的自动指标（如关键词命中、格式校验）；若选择「自定义」，则由用户自行填写任务描述、优化目标与评分标准。

任务描述用于指导变体生成（告诉大模型这个任务要做什么、评价什么），评分标准用于后续评审打分。测试用例集是任务执行与评估的输入，用户可逐条添加（每条包含输入与参考输出），也可通过 JSON/CSV 文件批量导入。系统对每个用例做合法性校验：输入必填、参考输出可选（无参考输出时仅能使用评审打分，无法计算 BLEU/ROUGE 等自动指标）。

创建成功后，任务进入「待运行」状态，并在任务列表展示任务名、类型、用例数、创建时间与当前最优分数。

#### 关键规则

- 预置任务类型模板：文本生成、文本摘要、信息抽取、代码生成，各含任务描述骨架、评分标准建议、适用自动指标建议和用例示例。
- 任务可分别配置执行模型与评审打分模型（评审模型留空则沿用执行模型），并可调自动指标与评审打分的合成权重。
- 用例导入支持 JSON、CSV 两种格式；导入后展示解析成功条数与失败原因。
- 每个任务至少需要 1 条测试用例才能进入迭代运行。
- 任务属于创建者，仅创建者可见可操作（数据按用户隔离）。

### 3.2 变体生成与执行模块

#### 页面布局

本模块由两个区域构成：

- **变体生成区**：基于当前最优提示词与失败案例生成多个变体，展示每个变体的摘要与改写思路。
- **批量执行区**：展示变体对全部测试用例的执行进度、成功/失败状态与输出内容，支持失败重试与并行粒度设置。

#### 业务逻辑

系统以当前最优提示词为基础，结合上一轮的失败案例（bad case）与优化目标，调用大模型生成多个提示词变体（默认同轮 4 个，数量可配置）。生成策略包含：失败案例注入（把上一轮表现差的用例作为反例融入提示词）、结构化改写（调整指令层级与约束表达）、约束显式化（把隐含要求显式写成硬性规则）。

变体生成完毕后进入批量执行阶段：对每个变体，依次调用大模型 API 执行全部测试用例，保存每次调用的输入与输出。系统支持并发执行（可配置并发数）以缩短单轮耗时；对超时、限流、接口异常导致的失败调用自动重试（默认 2 次），重试仍失败则标记该条为失败并在结果中注明错误原因。

执行过程中，前端通过轮询展示实时进度：已完成用例数、成功数、失败数。单变体单用例的调用结果作为评估阶段的输入，落库持久化以便复现。

#### 关键规则

- 每轮变体数量、并发数、重试次数均为可配置项，默认值见配置字段。
- 失败调用标记原因分类：超时、限流、接口错误、非法返回。
- 单轮内同一用例被多个变体执行，结果分别独立存储，不互相覆盖。
- 变体生成与执行可随时由用户中止，中止后已产生的结果保留。

### 3.3 质量评估模块

#### 页面布局

本模块由三个区域构成：

- **自动指标区**：展示每个变体在各测试用例上的自动指标得分（BLEU、ROUGE、关键词命中、格式合规等）。
- **评审打分区**：展示大模型按评分标准对每个变体的评审打分（1-10 分）及评分理由。
- **综合得分区**：按可配置权重合成每个变体的综合得分，并展示排名。

#### 业务逻辑

评估采用「自动指标 + 评审打分」双通道。自动指标由本地计算得出：BLEU 与 ROUGE 衡量输出与参考输出的 n-gram 重叠程度，适用于有参考输出的摘要、生成类任务；关键词命中校验输出是否包含必需关键词；格式合规校验输出是否符合预定义结构（如 JSON、列表、指定长度）。各指标得分换算到 0-100 分区间。

评审打分由大模型扮演评审角色，依据任务书中的评分标准，对每个变体在全部（或抽样）用例上的表现给出 1-10 分整数评分及理由。评分理由留痕，用户可以点开查看造成失分的原因。

综合得分由自动指标与评审得分按可配置权重加权合成（默认自动指标 50%、评审打分 50%；无参考输出的用例，自动指标权重自动降为 0，仅用评审打分）。评估结果按变体汇总，形成本轮排名，本轮最优变体的得分与排名最高的变体衔接进入下一轮迭代。

系统提供人工抽检通道：用户可对任意一条评估记录给出人工评分（1-10 分）与备注，用于校准自动评审与人工评分的一致性，支撑「一致率≥80%」指标的采集，并作为后续权重校准确参考。

#### 字段规则

| 字段 | 类型 | 必需 | 范围/说明 |
|------|------|------|-----------|
| BLEU 得分 | 数值 | 否 | 0-100，需参考输出 |
| ROUGE 得分 | 数值 | 否 | 0-100，需参考输出 |
| 关键词命中率 | 数值 | 否 | 0-100，需配置关键词 |
| 格式合规 | 布尔/数值 | 否 | 是否通过 |
| 评审打分 | 整数 | 是 | 1-10 |
| 评审理由 | 文本 | 是 | 打分依据 |
| 综合得分 | 数值 | 是 | 加权合成，0-100 |

#### 边界与异常

- 无参考输出的用例：自动指标不计算，跳过后仅用评审打分。
- 评审打分缺失：若大模型评审调用失败，该变体的评审分按上轮分值或中位数兜底，并在结果中标注。
- 全部指标为空：视为 0 分并给出提示。

### 3.4 迭代与报告模块

#### 页面布局

本模块由三个区域构成：

- **迭代进度区**：展示当前轮次、已迭代轮数、中止/结束状态，支持用户手动停止或冻结。
- **得分曲线区**：以折线图展示历史每轮最优得分的变化趋势。
- **报告区**：展示最终最优提示词、各版本差异对比、优化建议与导出入口。

#### 业务逻辑

系统编排「生成变体 → 执行任务 → 质量评估 → 择优更新 → 终止判断」循环。每轮结束后判断是否终止，触发条件为以下任一满足：最新最优得分达到目标分数、最优得分连续若干轮提升不足（默认连续 3 轮每轮提升小于 0.5 分即判定收敛）、或达到最大轮次上限。未满足则把当前最优变体作为下一轮基准继续迭代。

迭代被中途停止后支持断点续跑：重新开始时从上次已记录轮次的下一轮继续，已产生的用例执行与评估结果不重复计算；已完成的任务重新开始则从第 1 轮重来。未填写初始提示词时，系统在首轮前调用大模型按任务描述、优化目标与评分标准自动生成初始提示词。

迭代全过程保留完整快照：每一轮的版本（提示词文本）、得分、评分理由、变体集合均落库，支持回溯查看任意轮次状态。用户可在迭代运行中手动「冻结」某一版本（不再参与择优）或「回退」到历史某一轮重新出发。

迭代结束后生成优化报告：包含得分变化曲线、最终最优提示词、初始与最终提示词的差异对比（高亮新增/删除内容）、各轮次评分理由汇总与优化建议（如建议补充更多测试用例、调整评分标准表述等）。报告支持以 Markdown / JSON 一键导出。

#### 状态流转

| 当前状态 | 允许操作 | 下一状态 | 触发条件 |
|---------|---------|---------|---------|
| 待运行 | 开始迭代 | 运行中 | 用户点击开始 |
| 运行中 | 停止 / 冻结 | 已停止 / 已冻结 | 用户操作或达到终止条件 |
| 运行中 | 完成 | 已完成 | 达到目标分 / 收敛 / 最大轮次 |
| 已完成 | 查看 / 导出 | - | 用户操作 |

### 3.5 用户管理模块

#### 页面布局

本模块由登录注册区与管理区构成：未登录用户进入登录/注册页；登录后进入主界面，可按角色访问对应能力。

#### 业务逻辑

用户通过邮箱注册账号，注册后登录系统。系统按用户隔离所有数据：每个用户仅能查看和管理自己的优化任务、提示词版本与评测记录。存在两类角色——普通用户（创建与运行优化任务）与管理员（额外具备查看系统任务运行日志、管理用户状态的能力）。

管理员可管理用户：查看全部用户、调整用户角色（普通/管理员）、启用或禁用账号。被禁用的账号无法登录，其历史数据保留。

用户可保存和复用历史迭代记录：重新打开已完成的优化任务，可查看其历史版本、得分曲线与报告，也可以「基于该任务的最新最优提示词」作为新任务初始值再次运行。

#### 权限逻辑

| 角色 | 可见范围 | 可操作内容 | 数据隔离 |
|------|---------|-----------|---------|
| 普通用户 | 仅自己的数据 | 创建/运行/查看/导出自己的任务 | 按用户隔离 |
| 管理员 | 全部 + 运行日志 | 用户管理、日志查看 | 无隔离（仅限日志） |

### 3.6 知识库管理模块（RAG 检索增强）

#### 页面布局

本模块由三个区域构成：

- **知识库列表区**：展示用户创建的知识库，支持新建、删除与查看详情。
- **语料管理区**：上传/批量导入语料文档，一键导入示例语料目录，展示文档与分块数量。
- **检索与评测区**：输入查询词查看检索命中的知识块；对「检索 + 生成」结果进行来源支撑度与忠实度评测。

#### 业务逻辑

用户创建知识库后，可上传语料文档（支持单条录入与批量导入），系统将文档切分为知识块并建立索引：配置了嵌入模型（`EMBED_MODEL`）时使用向量检索，未配置时自动降级为本地词法指纹检索（无需外部依赖）。文档与块计数通过 SQL 原子自增维护，杜绝并发上传丢计数。

任务创建与迭代时可启用 RAG 增强：执行时检索相关上下文注入提示词，提升领域知识支撑。知识库提供「一键导入示例语料」能力，仅允许导入服务端配置的 `RAG_CORPUS_DIR` 目录，不接受任意用户路径。

检索+生成评测：对查询先检索 top_k 知识块，再让模型基于检索上下文生成答案，输出「来源支撑度」与「忠实度」两个 0-100 评分，量化 RAG 管线质量。

#### 关键规则

- 建库/文档/块三级结构，`doc_count`/`chunk_count` 必须原子自增，防止并发丢更新。
- 一键导入仅限服务端配置的 `RAG_CORPUS_DIR` 目录，防止任意路径文件读取。
- 查询侧嵌入失败时检索返回空列表（而非任意低分命中），避免注入错误上下文。
- 删除被任务绑定的知识库前，先解除任务关联（置空 `kb_id`/`enable_rag`），避免悬空外键。

### 3.7 在线服务模块（API 调用）

#### 页面布局

本模块由三个区域构成：

- **端点管理区**：将任务的最优提示词快照发布为可调用端点，展示端点列表与状态。
- **密钥管理区**：为每个端点生成 `sk-` 密钥，支持显示/隐藏、轮换与删除。
- **调用日志与统计区**：展示每次调用的时间、模型、耗时与状态码，以及今日/累计调用统计。

#### 业务逻辑

用户选择已完成任务与提示词快照版本创建端点，系统生成调用密钥（`sk-` 开头）。第三方系统通过 `POST /api/v1/endpoints/{id}/invoke` 携带 `X-Api-Key` 请求头调用，端点按快照提示词调用大模型并返回结构化结果。密钥轮换使用 urllib-safe 随机生成并通过 HMAC 恒定时间比较校验，防止时序攻击。

每次调用记录日志：调用时间、模型、输入摘要、耗时、状态码；调用次数统计使用 SQL 原子操作更新，避免高并发计数丢失。接口按端点维度限流（默认 60 次/分钟），防止密钥泄露后无限刷调用。

#### 关键规则

- invoke 接口仅支持 POST；鉴权使用 `X-Api-Key` 请求头，不依赖登录态（JWT）。
- 每个端点限流 60 次/分钟，超限返回 429。
- 密钥只在创建/轮换时返回一次明文；存储仅保存 HMAC 哈希。
- 在线调用依赖后端进程持续运行，后端停止则接口不可用。

### 3.8 模型评测平台模块

#### 页面布局

本模块由三个区域构成：

- **评测发起区**：选择任务与待评测提示词（最优 / 初始 / 自定义文本）、勾选多个模型、选定用例范围。
- **得分矩阵区**：以「模型 × 用例」矩阵展示各模型在每条用例上的综合得分与平均分。
- **评测报告区**：展示最优模型推荐、结论摘要，支持导出 Markdown 评测报告。

#### 业务逻辑

用户对同一任务的提示词发起多模型横向对比评测：系统用选定的多个模型分别执行全部（或选定）测试用例，按任务的自动指标与评审打分口径计算各模型 × 用例综合得分，形成得分矩阵。系统汇总每个模型的平均分并给出「最优模型推荐」（平均分最高者），供用户决策选用哪个模型落地该提示词。

评测运行记录与结果落库（`benchmark_runs` / `benchmark_results`），支持跨任务查看评测历史；评测报告可导出 Markdown 存档分享。

#### 关键规则

- 评测得分口径与任务迭代一致（自动指标权重 + 评审打分权重合成）。
- 每个模型 × 每条用例生成一条得分记录，矩阵完整可追溯。
- 评测期间任务本身可继续运行，互不影响。

### 3.9 多步骤工作流模块

#### 页面布局

本模块由三个区域构成：

- **工作流编排区**：创建/编辑多步骤工作流，为每步配置名称与指令模板。
- **执行历史区**：展示每次运行的逐步骤输出、耗时与基线对照评测结果。
- **步骤优化区**：对指定步骤发起多轮优化，展示择优回写与优化报告。

#### 业务逻辑

用户将复杂任务拆分为多个步骤链式执行：每步含指令模板，支持 `{{input}}`（步骤输入）与 `{{stepN.out}}`（第 N 步输出）占位符，上一步输出自动注入下一步。执行时按步骤顺序调用大模型，产出结构化结果并落库。

工作流支持基线对照评测：以用户预置的参考输出为基线，对整体输出计算自动指标得分。步骤级优化采用贪心迭代：对指定步骤的指令模板发起多轮优化（轮次可配 1/2/3/5），每轮生成变体 → 执行 → 评估 → 择优，连续两轮无改进或达最大轮次时提前终止，最优结果回写工作流并输出优化报告。

#### 关键规则

- 空模板或空步骤列表拒绝创建，与前端校验保持一致。
- 执行阶段在运行前构建一次检索器（RAG 场景），避免每个步骤重复查询数据库。
- 并发工作流运行创建在工作流粒度上加锁，防止同一工作流被重复触发运行。
- 步骤优化终止条件：达最大轮次或连续两轮无改进。

### 3.10 报告分享与仪表盘模块

#### 页面布局

本模块由三个区域构成：

- **分享中心区**：列出已生成的分享链接（优化报告 / 评测报告 / 工作流报告），支持复制、查看、撤销与有效期设置。
- **公开报告区**：通过分享 token 免登录只读查看报告全文。
- **仪表盘区**：资产总览统计卡（任务/知识库/端点/分享）、近 N 天得分趋势、模型使用分布、提示词版本库。

#### 业务逻辑

用户在任务详情/评测/工作流页面可将报告生成免登录分享链接：系统签发带随机 token 的链接并记录有效期（可设 1/7/30 天等），分享中心统一管理；撤销后 token 立即失效。公开报告页免登录只读展示报告内容，不暴露任何编辑能力。

仪表盘聚合展示用户资产：任务/知识库/端点/分享数量、近 N 天趋势（含当天）、各模型调用分布（SQL 聚合，非内存计算）、历史最优提示词版本库。版本库条目可一键定位到对应任务详情。

#### 关键规则

- 分享链接基于 token 机制，不暴露资源 id；跨用户访问被隔离。
- 报告分享只读，公开页无任何写操作入口。
- 趋势统计窗口包含起始日期（含当天），按指定天数返回逐日数据。

## 四、非功能性需求

### 4.1 内容合规

本产品生成的提示词变体、任务输出与评审意见由 AI 自动生成，优化结果仅供参考，正式使用前应经人工确认。依据《互联网信息服务深度合成管理规定》，对 AI 生成内容应以显著方式标识。

### 4.2 数据隐私与安全

用户的提示词、任务描述与测试用例可能包含业务敏感信息，系统应支持 HTTPS 加密传输、数据库安全存储，支持本地化部署；调用大模型 API 前对敏感字段进行脱敏；不得将用户任务数据用于服务以外用途或向第三方提供。

### 4.3 可靠性

调用大模型 API 存在可用性与限流风险，须设计超时与重试机制。单条用例调用失败不应阻塞整个迭代流程，失败结果留有原因与可重试通道。

### 4.4 性能

单轮迭代（含多变体 × 全量用例）需在 60 秒内完成（默认用例如下：4 变体 × 5 用例）。在大规模用例下采用并发执行与分批处理保证可接受耗时。

### 4.5 浏览器兼容

确保在主流浏览器（Chrome / Firefox / Safari / Edge）最新两个版本上正常运行，界面采用响应式设计适配 PC 与移动端浏览器。
