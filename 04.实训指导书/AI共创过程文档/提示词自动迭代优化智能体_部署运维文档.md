## 一、部署架构

本系统为**前后端分离**应用，前端为 React 静态资源，后端为 FastAPI 服务。

```
浏览器
  │
  ├── 开发模式（双进程）
  │    浏览器 → 前端 Vite(:5173) ──(proxy /api)──> 后端 FastAPI(:8000) ──> sqlite / LLM
  │
  └── 生产模式（单端口，推荐）
       浏览器 → FastAPI(:8000) 统一提供
                  ├── 前端静态页面（static/ + SPA fallback）
                  └── 业务 API（/api/v1/*）
                        ├── 任务 / 迭代 / 用例 / 评测 / 报表
                        ├── 知识库 RAG（向量 / 词法双模式检索）
                        ├── 在线服务（X-Api-Key 鉴权 + 限流）
                        ├── 多步工作流（执行 / 步骤优化）
                        ├── 报告分享（/share/:token 免登录只读）
                        └── 仪表盘统计（SQL 聚合）
                                          （可选）外置 Nginx 反代 + HTTPS
```

- **开发模式**：前端 `npm run dev`（:5173），后端 `uvicorn`（:8000），由 Vite proxy 联调。
- **生产模式**：前端构建产物放入后端 `static/`，由 FastAPI 静态托管，`http://域名:8000` 单端口访问。
- **依赖进程**：知识库「一键导入示例语料」读取服务器 `RAG_CORPUS_DIR` 目录；在线服务调用依赖后端进程（uvicorn）持续运行——后端停止则 `/endpoints/{id}/invoke` 连接失败。

## 三、开发模式启动

### 3.1 后端
```bat
cd 01.code\prompt_optimizer\backend
copy .env.example .env            # 首次
python -m uvicorn app.main:app --reload --port 8000
```
API 文档：http://localhost:8000/docs

### 3.2 前端
```bat
cd 01.code\prompt_optimizer\frontend
npm install                        # 首次
npm run dev                        # http://localhost:5173
```
开发代理已配置 `vite.config.ts`：`/api → http://127.0.0.1:8000`。

## 四、生产模式启动（单端口，推荐教学/演示）

cd 部署版code

## 五、生产部署（Nginx + HTTPS）

1. 上传 `部署版code` 至服务器，后台运行后端（内网监听）：
   ```bash
   # Linux/systemd 或 nohup
   nohup uvicorn app.main:app --host 127.0.0.1 --port 8000 > app.log 2>&1 &
   ```
2. 编辑 `nginx.conf` 填入域名，配置 80/443 + SSL 证书，反代到 `127.0.0.1:8000`。
3. 公网 HTTPS 环境将 `.env` 中 `COOKIE_SECURE=true`（浏览器仅经 HTTPS 传输登录 Cookie）。
4. 依据《互联网信息服务深度合成管理规定》对 AI 生成内容显著标识，本系统前端已内建「AI 生成」引导提示；建议部署于内网/受控环境。

## 六、环境变量（backend/.env）

| 变量 | 说明 | 默认 |
|------|------|------|
| `JWT_SECRET_KEY` | JWT 签名密钥，须用 `secrets.token_urlsafe(64)` 生成随机长串；部署版出厂为空占位并在启动时强制提示填写，禁止弱密钥 | change-me… |
| `JWT_ALGORITHM` | JWT 签名算法 | HS256 |
| `JWT_EXPIRE_MINUTES` | 登录有效期 | 1440 |
| `COOKIE_SECURE` | 公网 HTTPS 置 `true`；本机/内网 HTTP 保持 `false` | false |
| `LLM_BASE_URL` | 大模型 API（OpenAI 兼容，国内直连） | 空 |
| `LLM_API_KEY` | 大模型密钥 | 空 |
| `LLM_DEFAULT_MODEL` | 默认模型 | qwen-plus（项目实测 deepseek-ai/DeepSeek-V4-Flash） |
| `DATABASE_URL` | 数据库连接 | sqlite:///./prompt_optimizer.db |
| `VARIANT_GEN_TEMPERATURE` | 变体生成采样温度 | 0.8 |
| `EXEC_TIMEOUT_SECONDS` | 单用例执行超时 | 60 |
| `EXEC_MAX_RETRIES` | 失败重试次数 | 2 |
| `EMBED_MODEL` | 嵌入模型名（OpenAI 兼容 embeddings，如 `BAAI/bge-m3`）；**留空 = 本地词法检索**（零外部依赖） | 空 |
| `RAG_CORPUS_DIR` | 一键导入示例语料库目录（**仅允许本配置目录**，禁止任意路径，防任意文件读取） | 空 |
| `RAG_EVAL_TOP_K` | RAG 评测/执行时默认注入的检索块数 | 4 |

> 未配置 LLM 时：登录/任务/用例/知识库本地词法检索等可用；变体生成/执行/评审/迭代/嵌入检索需 LLM，填 Key 后重启生效。

## 七、全功能模块部署要点

- **知识库（RAG）**：`EMBED_MODEL` 留空即用本地词法指纹（无需外部依赖）；配置嵌入模型后自动切换向量检索。示例语料一键导入指向 `05.RAG语料/`（`RAG_CORPUS_DIR` 配置其绝对路径）。文档/块计数（`doc_count`/`chunk_count`）由后端 SQL 原子自增，多用户并发上传不会丢计数。早期版本数据库 Task 表若缺 `kb_id`/`enable_rag` 列，运行 `backend/reconcile_apply.py` 增量补列。
- **在线服务**：端点将任务最优/冻结提示词快照 + 执行模型固化为可对外调用的 POST 接口；调用使用 `X-Api-Key: sk-xxx` 请求头鉴权（HMAC 恒定时间比较，**免 JWT**，可被 curl/Postman/程序直接调用）；密钥支持轮换（轮换后旧密钥立即失效，历史日志保留）；按端点限流默认 **60 次/分钟**，超限返回 429；调用计数与统计由 SQL 聚合。
- **报告分享**：模型评测 / 工作流步骤优化 / 任务迭代三类报告可生成 `/share/:token` 免登录只读链接，支持限时（`expires_hours`）与撤销；访问计数原子自增。
- **多步工作流**：步骤指令模板支持 `{{input}}` / `{{stepN.out}}` 占位符链式解析；执行与步骤优化均为后端异步任务（工作流粒度锁防重复运行），同工作流并发发起由后端串行化临界区。

## 八、常见问题排查

| 现象 | 原因与处理 |
|------|-----------|
| 打开页面报 API 401 | 登录过期，前端已自动跳登录页，重新登录即可 |
| 登录提示被锁定 | 连续 5 次失败按「IP+邮箱」锁定 15 分钟，等待解锁或更换网络 |
| 迭代一开始就失败 | 未配置 `LLM_API_KEY` 或 Key 无效，检查 `.env` 后重启 |
| 一键导入示例语料失败 | `RAG_CORPUS_DIR` 未配置或路径不存在，指向 `05.RAG语料/` 后重启 |
| 在线调用返回 401 | 端点已停用 / 密钥错误 / 密钥已轮换，在「在线服务」页重新生成密钥 |
| 在线调用返回 429 | 触发 60 次/分钟限流，稍后重试 |
| 公开分享链接打不开 | 分享已撤销 / 已过期 / 令牌错误，重新生成链接 |
| 端口被占用 | 换端口：后端 `--port 8001`；前端改 `vite.config.ts` 并同步 proxy |
| 前端 `/assets` 404 | 前端构建后未同步到 `backend/static`，重新 `npm run build` + xcopy |
| 停止批处理误杀其他 Python | `stop_all.bat` 按命令行 `uvicorn app.main` 精确匹配，一般安全 |
| 上传大用例/语料文件失败 | 调整 Nginx `client_max_body_size`、后端 body 限制 |
| 老库报 no such column: kb_id | 早期版本库缺列，运行 `backend/reconcile_apply.py` 增量补列 |

## 九、安全与合规要点

- **密钥管理**：`.env` 含密钥，全项目 `.gitignore` 已忽略，勿提交版本库或公开仓库；部署版出厂 `.env` 为空占位并在启动时强制提示填写；若泄露立即在服务商控制台轮换密钥。
- **JWT 安全**：签名密钥必须随机生成（`secrets.token_urlsafe(64)`），禁止弱/可预测密钥（弱密钥可被伪造任意用户 token，含管理员）。
- **在线端点密钥**：`sk-` 前缀 urllib-safe 随机生成，鉴权用 HMAC 恒定时间比较防时序攻击；支持轮换；按端点限流（60 次/分钟）防刷调用；调用全程留日志与统计。
- **登录防护**：登录接口按「IP + 邮箱」失败计数与锁定（5 次失败锁 15 分钟），防暴力破解。
- **数据隔离**：所有资源访问校验 task_id + user_id 双重归属，防止跨租户读写；删除被任务绑定的知识库前自动解除任务引用，避免悬空外键。
- **分享链接**：token 唯一索引、支持过期与撤销、公开只读（不暴露编辑能力）、访问计数原子自增。
- **数据隐私**：任务数据默认本地 sqlite 存储，不经过第三方；生产建议启用 HTTPS、完善 `.env` 权限，敏感信息脱敏。
- **模型局限**：系统保留人工抽检通道（界面「人工抽检」），验证集/测试集隔离防过拟合，符合任务书对模型局限的约束。
- **浏览器兼容**：支持主流浏览器近两个版本。
