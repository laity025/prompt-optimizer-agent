## 一、测试概述

围绕「变体生成 → 任务执行 → 质量评估 → 择优迭代」核心链路，以及知识库（RAG）、在线服务、模型评测、多步工作流、报告分享、仪表盘等扩展模块，开展**单元测试、接口测试、端到端（E2E）测试、前端单测与性能测试**，验证功能正确性、数据隔离、权限控制、并发安全与整体性能。

> 说明：LLM 类能力（变体生成/执行/评审/嵌入）在测试中通过 `set_mock_client` 注入 `FakeLLM` 或使用本地词法指纹驱动，因此**无需真实 API Key 即可跑通完整迭代闭环与 RAG 双模式检索**，同时保证自动化测试可重复、无外部依赖。

## 五、缺陷与修复记录

### 5.1 P6 测试阶段（历史遗留，均已修复）

| # | 级别 | 缺陷 | 修复 |
|---|------|------|------|
| 1 | 严重 | 前端 `http.ts` 拦截器将 blob 下载当 JSON 解包，导出报告必然失败 | `responseType==='blob'` 直接透传 |
| 2 | 中等 | 前端导出/接口 `action` 参数位置与后端 query 契约不一致 | 改为 `params:{action}` |
| 3 | 中等 | 创建任务临时用例输入依赖表单未注册字段，会添加空用例 | 抽为独立 `caseInput` 状态 |
| 4 | 中等 | 任务列表行点击与操作按钮冒泡冲突 | 按钮点击 `stopPropagation()` |
| 5 | 低 | 人工抽检备注未回传前端 | 后端补 `manual_note` 返回 |
| 6 | 低 | 迭代页缺版本「冻结/回退」操作入口 | 补齐按钮 + 确认 + 刷新 |
| 7 | 低 | 得分曲线组件双 `useEffect` 定义重复 series | 重构为单一干净 option |
| 8 | 低 | 生产构建单包 2.3MB | `manualChunks` 代码分割 |

### 5.2 P8 功能扩展与安全加固阶段（新增模块联调 + 全量安全审查定位，均已修复）

| # | 级别 | 缺陷 | 修复 |
|---|------|------|------|
| 9 | 严重 | `backend/.env` 与部署包 `.env` 含真实 LLM API Key 且无 `.gitignore` 保护 | 立即在 SiliconFlow 控制台轮换密钥；清理全部 `.env`；全项目补 `.gitignore` 忽略 `.env` |
| 10 | 严重 | JWT 密钥弱且可预测（HS256 下可伪造任意用户 token） | 改用 `secrets.token_urlsafe(64)` 随机生成；部署版出厂空占位并在启动时强制提示填写 |
| 11 | 严重 | 登录接口无暴力破解防护 | 按「IP + 邮箱」失败计数，连续 5 次失败锁定 15 分钟，锁定期间返回 429 |
| 12 | 中等 | `review_eval` 接口仅校验 task 归属未校验 eval_id（IDOR） | 补 eval_id 归属校验，防止跨用户修改评测记录 |
| 13 | 中等 | 在线调用无速率限制，密钥泄露后可无限刷调用 | 按端点维度限流（默认 60 次/分钟），超限返回 429 |
| 14 | 中等 | 前端 token 存 localStorage，XSS 场景可窃取 | 改为 HttpOnly Cookie + 相关接口补 Content-Security-Policy 头 |
| 15 | 中等 | `benchmark_detail` / `export_benchmark` 归属校验不完整 | 补齐 task_id + user_id 双重归属校验 |
| 16 | 低 | `admin.py` 未导入 `state_error`，管理员「禁用自己」分支异常 | 补导入，分支功能正常 |
| 17 | 低 | SPA fallback 吞掉未知 `/api/v1/*` 路径，前端排错混淆 | 未匹配 API 路径返回 JSON 404 而非 index.html |
| 18 | 低 | 工作流并发锁字典 `_start_locks` 无清理，长运行服务内存缓增 | 增加定期清理机制 |
| 19 | 低 | 早期版本 SQLite 库 Task 表缺 `kb_id` / `enable_rag` 列，报 no such column | 提供 `reconcile_apply.py` 增量补列 |

## 六、遗留与说明

1. **真实 LLM 验证**：自动化测试用 `FakeLLM` / 本地词法指纹保证了逻辑正确性与可重复性；接入真实模型的效果（如 ROUGE 打分合理性、变体质量、嵌入检索排序）需在 `backend/.env` 填入有效 `LLM_API_KEY` / `EMBED_MODEL` 后进行人工/实测冒烟。
2. **前端单测覆盖**：当前聚焦纯逻辑（用例解析）；组件/交互层依赖浏览器，建议后续结合 Playwright 补充，作为可选项。
3. **接口层覆盖补充**：knowledge 端点层覆盖率（66%）低于服务层（rag_service 72%），主要为参数校验与异常分支未全覆盖，建议后续补充接口级用例。
4. **性能基准**：本性能数据基于单机 sqlite；数据量增大或并发升高时建议迁移至 PostgreSQL 并复核。
5. **安全声明**：依据《互联网信息服务深度合成管理规定》，AI 内容已在界面显著标识，建议本地化/内网部署。
